# Tota Scriptura Static Site Generator

The bespoke static site generator for [totascriptura.org](https://totascriptura.org). It turns the site's Obsidian vault into a static HTML site for GitHub Pages. `build.js` is the entry point, the generator proper lives in `lib/`, and the layout, CSS and fonts live in `template/`.

This reference was written from the code as of October 2026. It replaces the Replit-era `archive/replit.md`. Where the two disagree, this file is the correct one.

## Running

The content repo installs tsgen as a git dependency and runs its `tsgen` command from the vault root:

```jsonc
// totascriptura.org/package.json
"scripts": { "build": "tsgen" },
"devDependencies": { "tsgen": "github:joeyday/tota-scriptura-static-site-generator#v0.3.3" }
```

Commands (run from the vault root):
- `tsgen` or `tsgen build`: build the site and the book (what CI runs; see [The book](#the-book)): the site, and `<output>/book/book.pdf` with its covers, `<output>/book/cover.pdf` and `<output>/book/cover-dark.pdf`. The book is on by default and takes a few seconds more; `--no-book` builds the site alone (the way to be fast while writing), and `--book-html` stops the book at its layout, `<output>/book/book.html`, which it keeps (to look at it without Chrome). The book needs `book.json` in the vault and Chrome or Chromium (`CHROME_PATH` names it if it is not in a usual place); without them the build fails and says so.
- `tsgen serve`: build, then serve the output at <http://localhost:4000/> and rebuild when the vault or `template/` changes. The book is typeset in the background (the site is up at once) and served at `/book/book.pdf`; after each rebuild a new one is made, and the last good PDF stays up until it is ready. A book that fails (no `book.json`, no Chrome, a link out of the book) is reported and does not stop the site. `--no-book` serves the site alone. `serve.js` mimics GitHub Pages: `/foo/` serves `foo/index.html`, `/foo` redirects to `/foo/`, and unmatched URLs get `404.html` with a 404 status. It binds to localhost, and the port is 4000 unless `--port <n>` says otherwise. Unless you pass `--verbose` it prints only warnings, errors and the address it serves at (not the "Built …" and "processed …" lines `build` prints).
  - **Watching** (on by default; `--no-watch` serves the first build only): a change to a page, a data file (`.json`), an image or other asset, or a template file starts a rebuild after 2.5 s of quiet (`quietMs` in `lib/watch.js`; Obsidian saves a file more than once while you work, so a short wait rebuilds over and over), so a burst of saves is one build. A change that arrives during a build restarts that wait like any other; builds never overlap, and a change whose wait ends mid-build is rebuilt as soon as the build finishes. Each rebuild prints a `Changed: …` line naming the files that triggered it (the first five) and a `Rebuilt in … s.` line, with or without `--verbose`. Dot-folders (`.obsidian`, `.git`, `.claude`), the output folder, `node_modules`, and the never-built `CLAUDE.md`, `PLAN.md` and `README.md` are ignored. The whole site is rebuilt (about half a second) into a staging folder (`.dist-next` beside the output) and swapped in only if the build succeeds; if it fails, the error is printed and the last good site keeps serving. Served pages carry a small script that reloads them when a rebuild finishes (only while watching; the built site never has it). `serve` (with watching) runs as two processes, so that a change to tsgen's own code is picked up too: a small supervisor (`lib/supervise.js`) watches `lib/`, `build.js` and `serve.js`, and when one changes (after 1 s of quiet) it prints a `Changed: … Restarting.` line and starts the server over, because Node loads each module once per process and a rebuild alone would run the old code. The pages open in a browser reload themselves when it is back: the server tells each page which run it is on connecting (a boot id), and a page that reconnects to a different one reloads. If an edit leaves the code unable to start, the supervisor says so and waits for the next change to the code; it never restarts on its own. A build, and `serve --no-watch`, never load the supervisor, so none of this touches `tsgen`'s build or the published site.
- `tsgen serve --show-hidden`: the same, but the `hidden` property is ignored, so hidden pages build like any others (rough drafts, the sandbox page). Only `serve` takes the flag, so a deploy can't publish hidden pages. Problems that only a shown-hidden page causes (a broken link, a URL or alias clash, an abbreviation, initials or image with no entry) are warnings, not build errors. Flags can be combined: `tsgen serve --show-hidden --verbose --port 4001`.


For a local `tsgen` command, run `npm link` once in the tsgen repo. During tsgen development you can also run `cd vault && node ../build.js` (see `CLAUDE.md`).

The vault scan, `abbreviations.json`, `initials.json`, `alt-text.json` are resolved from the **working directory**. Output goes to `./dist`, or to the directory named by the `TSGEN_OUT` environment variable if set. CI sets nothing; locally it keeps build output out of the iCloud-synced vault (for example `export TSGEN_OUT="$HOME/Projects/tsgen/out"` in `~/.zshrc`). The template is resolved from tsgen's own directory.

The output directory is emptied at the start of every build, so deleted pages don't linger. The build refuses to clear a directory that is, or contains, the vault.

Dependencies: `yaml` (frontmatter), `markdown-it`, `markdown-it-footnote`, `markdown-it-mark`, `markdown-it-container`, `markdown-it-deflist`, `markdown-it-bracketed-spans`, `markdown-it-attrs`, `ejs`, `slugify`. The search page loads `minisearch@7.2.0` from jsDelivr (pinned, with an SRI hash) at runtime.

## Inputs

`template/` (in tsgen) holds `layout.ejs` and the site's CSS and JS. Icons come from a Font Awesome Pro kit that the layout loads as a script (`kit.fontawesome.com/….js`, deferred): the kit swaps each `<span class="fa-…">` for an inline SVG, so the kit's own settings decide which icons exist. The Pro licence forbids publishing standalone copies of the SVGs, so they aren't self-hosted. `statistics.css` holds the styles for `/statistics` alone; the page passes `stylesheet: "statistics.css"` to the layout, which links it after `style.css` (so it can override the site's defaults) on that page only. `/statistics` loads a second kit (`ecf9c95079`, with the core icons plus its own) instead of the main one; the layout's `kit` value picks it. `css-naked.js` is CSS Naked mode (below). `abbr-popover.js` is the tap-an-abbreviation popover (see the abbreviations pass), and `print.js` fills in the print date. The text fonts are open-source subsets, self-hosted in `template/fonts/`: Source Serif 4 for the text (renamed "Tota Serif", since its licence reserves the name "Source"), with Noto Serif ("Noto Serif Supplement") for Greek and for the transliteration letters Source Serif lacks (it has no polytonic Greek and only part of Latin Extended Additional: `ḵ ḇ ḳ ẖ ə` and more), listed first in the stack with a `unicode-range` of exactly those characters, a little lighter and 92% of the size to sit beside Source Serif; combining marks aren't covered, so write the precomposed letter. Hebrew is Noto Serif Hebrew (no italic). The Fira stacks fall back to sans fonts instead: Noto Sans Supplement (the few Greek letters Fira lacks and the transliteration letters it lacks) and Noto Sans Hebrew, both pinned to Noto Sans's semi-condensed width and a little lighter than 400 and 700; Fira Sans Condensed for headings (each Fira face has a `-Greek` twin file with a `unicode-range`, so a page downloads Fira's Greek only when it has Greek in a Fira context), Fira Sans Compressed for secondary text (navigation, footnotes, search; Book, 350, for the 400 the CSS asks for and SemiBold, 600, for 700; Condensed's SemiBold is for bold in a heading or table header and loads only when a page has one), and Fira Mono for code, all with the OFL licences beside them. `scripts/subset-fonts.py` builds the files from the upstream releases (what it keeps is in its header); run it only when the faces, the character set or the upstream version changes. The `@font-face` rules are in `template/fonts.css`, which the layout and the book both link, and use `font-display: auto`. The three icons in `template/favicon/` (`favicon.ico`, a 96px PNG and the 180px touch icon) are rasterized from the Pro feather-pointed icon; the layout's head links exactly those. Its assets are copied to `dist/asset/` along with the vault's.

**Sizing.** Everything is in `rem` and `em`, so the page follows the reader's default font size (16px unless they changed it in the browser). The root font size is `max(1rem, min(4.267vw, calc(1.375rem - 0.5pt)))`: it grows with the window (4.267vw, 14px at 328px wide) up to 1.375rem less half a point, 21.33px, at 500px wide, and holds there. Holding it constant is what makes page zoom exact (zooming narrows the viewport, and a size that kept growing with the window would shrink by part of the zoom). The column is always `1/0.04267` rem wide (23.4em, 500px at the cap; `--main-width`: the `0.04267` is the `4.267vw` above, so the two change together), at most the viewport, so it grows and shrinks with the text. The sidebar appears from `50em` (800px at 16px), where the body, 37.16 root sizes wide (793px at the full 21.33px), just fits; below that the page is one column, centered. The breakpoints are in `em` too, so at a larger default size the sidebar waits for a wider window instead of squeezing the column, and the text keeps the same line breaks at every default size. On a screen too narrow for the column the text can't stay at 23.4em, so it reflows to fewer characters per line. The text is never smaller than the reader's default size (`1rem` is the floor), which is also what lets page zoom enlarge text on a phone. In a media query, `em` is the browser's default size, so the thresholds follow that too.

The rest come from the vault:

| Path | Required | Purpose |
|---|---|---|
| `**/*.md` | | Pages. Skipped directories: `node_modules`, `dist`, `.git`, `.github`, `.local`, `template`, and any dot-prefixed directory. Skipped files, in any folder and whatever their case: `CLAUDE.md`, `PLAN.md` and `README.md` (notes and docs that live beside the content; they are never pages, partials or errors). |
| `image/**/*.{png,jpg,jpeg,gif,svg,webp,avif,ico,bmp,css,js,eot,otf,ttf,woff,woff2}` | | Copied flat into `dist/asset/`, together with tsgen's own `template/` assets. Assets anywhere else in the vault are ignored. Names are flat in `dist/asset/`, so two files with the same name (compared case-insensitively) **fail the build**, listing both. |
| `abbreviations.json` | **yes** (a missing or malformed file fails the build) | `{ "term": "expansion" }`; a value that is null or empty fails the build |
| `initials.json` | **yes** (same) | `{ "R.C. Sproul": "Robert Charles" }`: the initials and the surname, then what the initials stand for |
| `alt-text.json` | **yes** (same) | `{ "image-basename.png": "alt text" }` |

## The book

The book is part of the build: `tsgen` typesets the site as a print book (4.25 × 6.8598 in, mirrored margins, the trim size of the 2020 book), in the site's own fonts. It is made from the *built* site, so every text pass (abbreviations, small asides, ellipses, Roman numerals, divine names) has already run on the words and the book can't drift from the pages.

- **`book.json`** at the vault's root says what is in the book and in what order, the way `abbreviations.json` does for abbreviations: `{ "parts": [{ "title": "Prolegomena", "topics": ["Scripture", "Old Testament canon"] }, …], "index": { "groups": ["Church", "Preservation"] } }` (the groups are for the topic index below). The order of the file is the order of the book. A topic is named as a wikilink names it (a bare name looks in `topic/` first; `topic/Trinity` is exact). Anything that is missing, ambiguous, hidden, a draft, a notes page, a category or listed twice fails the book with every problem named, and `book.json` itself is checked (valid JSON, a non-empty `parts` list, each part with a `title` and `topics`, and `index.groups`, when given, a list of headings). The site build never reads it.
- **The generator owns the rest** (`lib/book/compose.js`): a title page and a copyright page laid out as the printed 2020 book's are (the title in serif small caps over a sans subtitle and author; a narrow column of small sans type, ending with the "personal use" line at the foot), a dedication, a short table of contents (the Preface, each Part, the Topic index and the Scripture index: the indexes are how to find any one topic or verse), the **Preface**, each Part page and its topics, and the two indexes. The copyright page's edition line gives the month and year (which name the edition), then the content commit and the tsgen version the book was made from, in that order so the generator's version isn't mistaken for the book's, so a book always says what it came from. The preface is the vault's About page (`/about`), retitled; when there is no published About page there is no preface (a foreword is written by someone else, and this is the author's own account of the project).
- **The Topic index** lists every topic in the book and every `aliases` entry of one ("Communion" for the Lord's Supper), each with the page its topic starts on, sorted ignoring leading articles and case. `index.groups` are headings that gather entries: with "Church", "Church discipline" is "discipline" under "Church", which has a page of its own if a topic is called Church; with "Preservation" (no topic of that name) the heading has no page and gathers "of Scripture" and "of the saints". A heading nothing matches doesn't print.
- **The Scripture index** is a plain list, not the site's: every Bible reference cited in the topics (read from the links the site already made, whose `ref.ly` addresses say exactly what each one is, so "2Jn 1, 13" is verses 1 and 13 of 2 John; the Preface isn't indexed), books in canonical order, each reference once, in two narrow columns, followed by the pages it is on (a page once, however often it is cited there; a book heading never ends a column). A 42-topic book has about 5,400 references, 3,400 of them unique, and the index runs to about 42 pages. It closes with a centered line in small sans type: "The 43 topics and commentaries in this edition cite 4,775 of the Bible's 31,102 verses, 15% of all Scripture." The figures are the site's own count (`scriptureStats`: a verse is cited by a passage of at most fifteen verses), and "and commentaries" is there only when a page comes from `commentary/`.
- **What a topic becomes:** the page's `<article>` without its header, categories line and icons. A Bible reference or web address is its plain text, and an "External links" section is left out (the book prints no web addresses of its own); a link to a topic that is in the book is a cross-reference, "Monotheism (p. 27)"; Footnotes are the topic's endnotes, numbered from 1 in the order cited, with no heading. The three places that point out of the book are trimmed silently: "See also" keeps only the topics that are in the book (and goes when none are), a "Main topic" line keeps only its topics that are in it (and goes when none are), and an inline "— see also Eternal" goes when it names only topics outside the book. **Any other link to a page that is not in the book fails the book**, naming the link and the topic it is in, so a stray pointer never reaches print. A commentary (name it with its folder, `commentary/Titus`, in a Part of its own) loses its outline and the Scripture index entries between its paragraphs, with their switch, and sets each term in bold running into its definition, as on the site; its paragraphs may split across pages, and its own Bible references join the Scripture index. Ids are prefixed with their topic's, so two topics' "Oneness" headings don't collide. A term is never separated from its descriptions (`.claim`): a claim of about ten lines or fewer moves whole to the next page, and a longer one may break inside a description, with at least two lines on either side. Inline colour (a pink asterisk in a table) prints black.
- **Page numbers are ours** (`lib/book/folios.js`, which runs inside the page after Paged.js has laid the book out): the front matter (title, copyright and dedication pages, contents, preface) counts in lower-case Roman numerals from the title page (i) and shows its number only on the contents and preface pages (v, vi; vii, viii …); the book proper restarts at 1 in Arabic on the first Part's page, which shows no number, as no Part page does; and a blank page still counts, so every chapter starts on a right-hand page. The same step fills in every cross-reference, contents line and index entry, repeats removed (each is a `data-p` or `a.pn` placeholder of "000" in the layout, so line breaks are never optimistic), and fails the book if one points at nothing.
- **A Bible reference never breaks across lines** ("Rev 1:1–3" used to split after its dash and leave a lone "3"; 69 lines in the book did): each reference in a topic is wrapped (`<span class="ref">`, which the Scripture index uses too) and set `white-space: nowrap`. References in the Preface or in a claim line (a term) aren't wrapped.
- **Hyphenation and widows:** running text is hyphenated (`hyphens: auto`, English), but not in headings, claim lines or the indexes, and `hyphenate-limit-chars: 6 3 3` keeps Chrome from hyphenating short words or leaving fewer than three letters on either side (about 2.7% of lines end in a hyphen, none three in a row). `orphans` and `widows` are 2 everywhere; only a few paragraphs ever split across a page (a claim never does), and none leaves a single line.
- **Typesetting** is Paged.js (a polyfill for CSS paged media) in headless Chrome, printing to PDF: `template/book.css` is the page setup and the styles, and links `template/fonts.css`, the same `@font-face` rules the site uses.
- **Paged.js constraints worth knowing:** `book.css` can't use `counter-reset` for any counter but `page` or `target-counter()` (Paged.js reads each page's `counter-reset` as a number to find a cross-reference's page, so another counter makes every later number 0; that is why footnotes are endnotes and why the page numbers are ours), can't use a sibling combinator in a selector list, and `leader()` in a contents line loses its page numbers (the contents use a flex row instead).
- **The cover** (`lib/book/cover.js`, styled by `template/cover.css`) is printed beside the book, as `<output>/book/cover.pdf` (and, for fun, `cover-dark.pdf`, the same cover in the site's dark theme: the dark sidebar's gray for the field over the dark page's, with light type): one flat sheet, the back, the spine and the front, with an eighth of an inch of bleed all round, as a printer wants it. It follows the 2020 cover (`Cover 1.0rc1.pdf`: a field in the site's sidebar gray (`--color-nav-background`, so the cover matches the site; test-checked) cut by a 45° diagonal, the title in serif small caps over the subtitle, a short rule and the author on the front, the title and author down the spine, 2 Timothy 3:16–17 in italic on the back), in the book's own fonts, with the Font Awesome feather-pointed icon (the site's logo) in place of the old feather. The icon is the kit's, loaded by script like the site's (`FONT_AWESOME_KIT`, in `lib/layout.js`, which the cover shares), so printing the cover needs the network; the SVG itself is never kept here, and a cover whose icon didn't load fails the book. The sheet's size is a whole number of points (rounded up into the bleed), and the PDF's page is cut down to it from the printed one, which Chrome sizes to a hundredth of an inch: a page a fraction of a point too large shows up in Safari and Preview as a hairline of white around the cover. The sheet is as wide as the spine is thick: the book's page count (as typeset, rounded up to a whole leaf) times `PAPER` in `cover.js`, which is a placeholder (KDP's white paper, 0.002252 in a page) until a printer and a paper are chosen. The spine's title is white and its author black, since the diagonal crosses the spine between them. `--book-html` stops before the PDF, so there are no covers then.
- **Output:** `<output>/book/book.pdf`, `cover.pdf` and `cover-dark.pdf`, and only those: the layouts they are typeset from, `book.html` (it needs `../asset/`, so it sits beside the site's assets) and the covers' HTML, are deleted (`book.html` is kept when `--book-html` stops the book there). A page at `/book` would be overwritten, so it fails the book. The 42-topic book is about 205 pages (about 43 of them the Scripture index) and takes about 7 seconds, including the site build; every page number in an index is a clickable link in the PDF.

## URLs

- **Slug**: the `permalink` frontmatter value (leading `/` stripped, otherwise used **verbatim**, not slugified), or else `slugify(filename, {lower, strict})`.
- **URL**: `/{relDir}/{slug}`. Folder names are used verbatim, keeping their case and spaces. Two non-hidden pages at one URL fail the build.
- **Folders**: Markdown may live only in the root, `topic/`, `category/`, `commentary/`, `reference/`, `partial/`, each of the others' `notes/` folders, and the root `notes/`. Markdown anywhere else fails the build. So does an iCloud placeholder (`.Name.md.icloud`), since the file isn't downloaded.
- **Notes pages**: a file in `notes/` (root) or `<folder>/notes/` is the notes page for the page of the same name in the parent folder. Its URL is the page's URL plus `/notes`: `topic/notes/Foo.md` is `/topic/foo/notes`, and the home page's notes are `/notes`. A `permalink` on a notes page is ignored. A notes page needs no page: with none, it still builds, at the URL the page would have, and its "Topic" link is greyed out. It is left out of the alphabetical index, the random pool and the Scripture index. Hide it with `hidden: true` like any page. So `/topic/foo` and `/topic/foo/notes` are reached from each other by adding or removing `/notes`.
- **Homepage**: a *root-level* file whose slug is `home` or `index` becomes `/`. In practice that means a file named `home.md`/`index.md` or `permalink: home`/`index`. (`permalink: ""` or `/` does **not** make a homepage: an empty permalink falls back to the slugified filename.)
- **404**: the URL `/404` is written to `dist/404.html` instead of `dist/404/index.html`. `404.md` is always `unlisted`, whatever its frontmatter says.
- Each page is written to `dist/{url}/index.html`. An empty `dist/.nojekyll` is always written.

## Frontmatter

Frontmatter is a YAML block between `---` lines at the very top of the file (`lib/frontmatter.js`, parsed with `yaml`). A file without one has none. A block that is never closed, or isn't valid YAML (or isn't a set of `key: value` pairs), fails the build, listing every offending file. That includes files in `partial/`, whose frontmatter is otherwise ignored.

Keys are lowercase (`title`, `featured with`). A key with any capital letter, such as `Title:`, fails the build, since it would otherwise be silently ignored. A `title` or `permalink` that is a number (`title: 1984`) is read as text; any other non-text value fails the build.

| Key | Effect |
|---|---|
| `title` | Display title. Defaults to the filename without `.md`. A notes page gets " notes" appended (`Trinity notes`) wherever its title appears: its heading, search, backlinks lists, alias redirect pages. A backlinks page is titled `{title} backlinks`. |
| `permalink` | URL slug (see above). |
| `description` | The page's meta and Open Graph description. Defaults to the first paragraph that has text, as plain text trimmed to about 160 characters at a word boundary; generated pages and placeholders get a site-wide default. Every page also carries `og:title`, `og:url` (`https://totascriptura.org` + the URL), `og:site_name` and `twitter:card`. When a content page body opens with an image embed (its hero), that image is the `og:image` and the card is `summary_large_image` (`summary` if the embed is square-ish). Every other page shares one fallback image, `image/Trees-and-buildings.png` (always `summary_large_image`): pages without a hero, generated pages, placeholders, and the **home page** (whose opening image is the avatar). A **notes page** shares its page's hero, never its own opening image (a diagram or map); with no page hero, or no page, it gets the fallback. The build fails if the fallback file is missing. |
| `hidden` | No page is generated. Hidden pages are left out of every index, search, the random pool, backlinks, notes links and categories, and their `aliases` write no redirect stubs. **Exception, a placeholder:** a hidden page that a published page links to by wikilink (links from hidden pages don't count, and neither do category membership or the generated tabs) builds as a placeholder at its URL: the title and an "under construction" notice (`fa-person-digging`, "This topic page is under construction."), `noindex`, none of its content. A placeholder is in no index, search, Scripture index or random pool, has no backlinks page and no alias redirects, and links to it get the `planned` class (pink, like `broken`). A hidden page nobody links to builds nothing. With `serve --show-hidden` the page builds and shows the notice "This topic page is hidden." (a notes page: "These notes are hidden.") in place of the draft notice, if it is also a draft. |
| `unlisted` | The page is built and links to it count as valid. It is left out of all index pages (including the Scripture index), search, the random pool, featured/featured-with, and category membership. It still takes part in notes links and backlinks. |
| `draft` | Listed on `/index/drafts`. Links to it get the `draft` class. The page shows "This topic page is a working draft." (the namespace varies; a notes page says "These notes are a working draft."). |
| `featured` | Listed on `/index/featured`. Gets a star on the alphabetical indexes. Links to it get the `featured` class. |
| `featured with` | Value is a page name or `[[wikilink]]`. Shown as "(and …)" after the target on `/index/featured`. Gets a star on the alphabetical index. |
| `categories` | A string or list of page names/`[[wikilinks]]`, each naming a page in `category/`, by basename or as `category/Name` (case-insensitive). A page in `category/` is a category page. A category with no listed members is made `unlisted` automatically, which can empty its parent category in turn. A name with no matching page logs a warning and renders as a broken link. |
| `aliases` | A string or list. Each alias writes a meta-refresh redirect at `/{relDir}/{slugify(alias)}`, is listed on its namespace's alphabetical index as "Alias (see Title)". It is not a wikilink target (`[[Alias]]` fails the build, as for any unknown name), and it can't contain a `/` (the build fails). If the page has a notes page, the alias also redirects `/{relDir}/{alias}/notes` to it, so a notes page has no aliases of its own (the build fails if it does). |

For all page-name values, `[[Page|Display]]` is reduced to `Page`.

## Link resolution

`resolveLink` is used for wikilinks and `featured with`:

1. If the target contains `/`, it is **path-qualified** and matches the file at exactly that path from the vault root, case-insensitively: `topic/Trinity`, `topic/notes/Trinity`. There is no suffix matching.
2. Otherwise the target is looked up in `fileMap`, which is keyed by the lowercased basename and the permalink.
3. When several candidates match, notes pages are dropped unless nothing else matches. Then the candidate in the source page's own folder wins (a notes page counts as in its page's folder), then the one in `topic/`, then the one at the vault root. When a tiebreak decides, a warning asks you to qualify the link. If none applies, the result is ambiguous: the build fails (see Wikilinks).


## Per-page pipeline

For each non-hidden page, in order. Code (fenced blocks and inline code spans) is masked first, so steps 1–6 never touch it, and it is restored just before markdown-it. Indented code blocks are not recognised as code (four spaces is also how list items continue).

1. **Partials**: `{{name}}`, `{{[[name]]}}` and `{{name|arg1|arg2}}` are replaced by the body of `partial/name.md`. Only the `partial/` folder (flat, no subfolders) is consulted. The name is matched by basename, case-insensitively, with no path syntax, aliases or permalinks. Everything in `partial/` is a partial and never a page: no frontmatter is read from it (any that is present is stripped and ignored), it is not in the link maps, and it has no URL, alias redirects or backlinks. Inside the partial's text, `{{1}}`… are replaced by the arguments, unfilled ones become empty, `{{$args}}` becomes the arguments joined by `, `, and `{{$n}}` becomes the argument count. Partials are expanded recursively, and a circular partial is replaced by a comment with a warning. A `|` inside `[[…]]` does not split arguments. A bare numeric `{{3}}` anywhere becomes empty. A call that follows a definition marker (`: {{name}}`) is a definition: the expansion's other lines are indented to stay inside it and its trailing line breaks are dropped, so the next `: ` line still follows directly.
2. **Wikilinks**: `[[Target]]` and `[[Target|Text]]` become Markdown links. One that matches no page, or several, **fails the build** (all of them are listed, with the page that holds each), but only on pages that get published: a hidden page is never rendered, so a bad link there is ignored. Links inside `%%comments%%` and code are ignored. The link text is the raw inner text, not the target's title. A `.md` suffix is stripped. A leading `!` on a non-image wikilink is ignored. `#heading` fragments are not supported and produce a broken link.
   Image targets (by extension) are looked up in the asset map, by real path (`image/img.png`, which is what Obsidian's link picker inserts; `template/img.png` for tsgen's own) or by bare filename (`img.png`, always unique, see the asset table). An image that is in neither folder, or doesn't exist, **fails the build** like a broken page link (published pages only), listing each one with its page. Alt text and link text default to the bare file name.
   - `[[img.png]]` becomes a link.
   - `![[img.png]]` becomes `<figure><img alt="img.png"></figure>`.
   - `![[img.png|Alt]]` sets the alt text.
   - `![[img.png|300]]` and `|300x150` set the dimensions.
   - **An embedded SVG is inlined**, as `<figure class="diagram"><svg>…</svg></figure>`, not linked as an `<img>`. Inline, its own `<style>` sees the page: the theme override (`:root[data-theme="dark"]`), `--color-main-text`, `--font-secondary`. The SVG scopes its rules under a class of its own, since the file's CSS is global to the page (a rule on `.trinity` hit the whole page, which carries the page's name as a class), and carries its own `<title>` for screen readers. The file's XML prolog and blank lines are dropped, and a `|300x216` size replaces the root's `width` and `height`. The text passes (abbreviations, divine names and the rest) skip `<svg>`, so a diagram writes a divine name by hand (`<tspan class="divine-name"><tspan class="divine-name-initial">G</tspan>OD</tspan>`). A plain link to an SVG (`[[x.svg]]`) is still a link to the file.
3. **EJS**: the whole page body is rendered as an EJS template with `frontmatter`, `fileMap` and `imageMap`. It is skipped when the body has no `<%`. If rendering fails, the build fails.
4. **Comments**: `%%…%%` is stripped right after the partials are expanded, before wikilinks and EJS, so a commented-out link or template tag does nothing.
5. **Small text** (inside markdown-it, as an inline rule in `lib/markdown.js`): `~text~` becomes `<small>`. It pairs like emphasis, so a pair stays inside one paragraph, heading, table cell, term or definition (never across a blank line or from a term to its definition) and may span a line break within one; a lone `~` stays a tilde; `~~` is strikethrough; code is untouched; a pair that would cross other markup (`~a *b~ c*`) can't make crossing tags. An opening `~` needs a non-space after it, and a closing one a non-space before it. A parenthetical in a term or definition (outside commentary), and an em dash with what follows it in a definition, are made small later, without tildes (see Post-processing).
6. **Fenced-div attribute protection**: `::: {…}` attributes are protected from `markdown-it-attrs`.
7. **markdown-it**: rendered with `html`, `linkify`, `typographer`, footnotes, `==mark==`, `~~strike~~`, tables (each wrapped in a `<div class="table-scroll">` that scrolls sideways), bracketed spans `[text]{.cls}`, generic attributes `{.cls #id k=v}`, containers, and description lists (below). Every `:::` fence becomes a `<div>`: a bare one is a callout (`<div class="callout">`, centred text), and `::: a b` produces `class="a b"`, and `:::{.a .b #id k=v}` sets the full attribute set. **Description lists** (`markdown-it-deflist`): a line of text followed by `: definition` lines is a class-less `<dl>` of `<dt>` terms and `<dd>` definitions. A topic, notes or reference page uses one for each section title and what is under it: the term is the section's title, set like an h3 (it gets an id), and its definitions are the muted, indented text under it (a "Main topic" line is the first one). A commentary page uses them for its verse commentary: the term is a bold phrase (the verse reference, then the phrase, italic in the Markdown), which runs into its definition with a period after it (the period is CSS). A term that begins like a list item (`1. Text`) reads as an ordered list, so write `1\. Text`. The lists with a class of their own are generated: the Scripture index's (`dl.scripture-entries`) and the statistics' tiles (`dl.facts`).
8. **Layout**: `template/layout.ejs` is rendered, then **link classification** runs on the whole page:
   - `http(s)` links get `external`, plus `bare-url` when the link text is the address itself (ignoring the scheme, `www.`, case and a trailing slash). Everything else gets `internal`.
   - Absolute paths (`/…`) can also get `draft`, `category`, `notes`, `featured`, `planned` and `broken`. A path is `broken` when it is not a known URL and not under `/index/`.
   - Only double-quoted `href`s are classified.

Steps 1–6 are plain regex passes over the raw Markdown, outside code.

### Print

The footer's links are About (left out below the sidebar's width, where the sidebar has it, along with its middot), Colophon and Settings, separated by middots, and under them, in a paragraph of their own with an em of space above, the social icons (Mastodon, Bluesky, Facebook, Ko-fi: icon only, each with a visually hidden name, in the footer's plain link color, not the brand colors). `style.css` ends with a print stylesheet, and the layout's footer carries a print-only line, "Retrieved from {canonical URL} on {date}", above the copyright. `print.js` fills in the date when the page loads and again on `beforeprint`; without JavaScript the line leaves the date out. In print the page is the article and nothing else:
- The logo, both navs, the quick nav, the namespace menu, the search form, the featured star, the footnote back-links and the categories line are hidden, as is the footer's line of links.
- Links are plain text. An `external` link spells out its address in parentheses, except `bible-ref` links (Scripture references stay bare) and `bare-url` links (their text already is the address).
- Tables have horizontal lines only: a gray header row (the nav gray, with white text) over rows alternating the page background and a light tint of it, a 1px line between the body rows in the thin-stroke gray, the same as the rule under an h2 (none under the header or the last row). The semantic colors are named by role (`--color-link`, `--color-link-external`, `--color-link-broken`, `--color-quote`, `--color-highlight`) and each is one of the twelve theme hues.
- Print is always light, even on a dark-mode machine (the dark colors apply to `screen` only). Colors are kept, and `print-color-adjust: exact` makes browsers print backgrounds (mark highlights, table headers) without the "background graphics" option.
- Headings follow a type scale: h3 keeps its size, h2 is one step up and h1 two, each step `--print-scale` (1.667) times the one below, so about 18pt and 31pt against the 11pt body.
- Callouts keep their screen width (the screen column is 1/0.044 rem, less the article's padding), so their text wraps at the same words.
- The type is a fixed 11pt in a full-width column with page margins of 1in above and below and 1.5in at the sides and page numbers (where the browser supports `@page` margin boxes). A heading, or a topic page's term, stays with the text after it (including a "Main topic" line between them), and figures, blockquotes and table rows don't split across pages.

### Layout template variables

`frontmatter`, `bodyClasses`, `content`, `nsLabel`, `view`, `pageUrl`, `noteUrl`, `backlinksUrl`, `categories`, `subcategories`, `pages`, `featured`, `featuredWith`, `stylesheet`, `kit` and `shownHidden` (true for a page that `serve --show-hidden` shows despite `hidden`).

- `bodyClasses`: the URL's path segments, or `["home"]` for `/`.
- `nsLabel`: the page's folder name, capitalised, plus " page" (`Topic page`, `Commentary page`), or `Meta page` for root pages. A notes page uses its page's folder. Generated pages have no Notes or Backlinks tab: the alphabetical, featured and Scripture indexes show a lone `Index page` tab, search and settings show a lone `Search page` or `Settings page` tab the same way, and the random page has no page-actions nav at all. (Backlinks pages have their own Backlinks tab.)
- `view`: which tab is showing: `page`, `notes` or `backlinks` (null for generated pages other than backlinks, which show no Notes or Backlinks tab). `pageUrl` is the page's own URL (null for a notes page whose page doesn't exist or is hidden). `noteUrl` is the notes URL, or null. `backlinksUrl` is the page's backlinks page, or null when the page is missing or hidden.
- `categories`, `subcategories`, `pages`: arrays of `{title,url}`. `subcategories` holds members that are category pages, and `pages` holds the rest.
- `featured`: true only for `featured: true`.
- `stylesheet`: the name of one extra stylesheet in `template/` to link after `style.css` (`/statistics` sets `statistics.css`, `/settings` `settings.css`), or null. `kit`: the Font Awesome kit id for the page's icons (the main kit unless the page passes its own; `/statistics` does).
- `featuredWith`: the raw page-name string, or null.

## Generated pages

- **Backlinks**: `/{url}/backlinks` (or `/backlinks` for `/`) for every non-hidden page that isn't a notes page. It lists the non-hidden pages whose wikilinks resolve to the page and, in a second section below, those that resolve to its notes page. The two sections get headings ("Links to the topic page", "Links to the notes"; the kind comes from the folder: topic, category, reference, … or meta for root pages) only when there is a notes section. An empty list says "No pages link to this topic page." Its Topic/Notes/Backlinks tabs match the page's and its notes page's, with Backlinks selected; a notes page's Backlinks tab points here. This is counted on partial-expanded Markdown with code and comments removed, before EJS. A page's links to itself are not counted.
- **Alias redirects**: written after the pages. The build fails if an alias would replace a page, or two aliases redirect the same URL to different pages.
- **Indexes**:
  - `/index/alphabetical/{namespace}`: one list per namespace, for `topic`, `commentary`, `reference`, `meta` (the root) and `category`, in that order (also the order of the menu). Each lists that folder's pages that are not hidden, unlisted or notes pages, plus their aliases. A namespace with nothing listed has no page and no menu entry. Each list starts with a menu linking to the other namespaces' lists, on two lines (`Topics · Commentaries`, then `Reference · Meta · Categories`); a line or entry with nothing listed is left out. `/index/alphabetical` is a stub that redirects to the Topic list.
  - `/index/categorical`: a flat list of top-level category pages only: category pages that are not hidden, not unlisted (so not empty) and not themselves in a category.
  - `/index/featured`
  - `/index/drafts`

  All lists are sorted ignoring a leading "A/An/The" and ignoring case.
- **Search**: `/search`, `dist/search-index.json` and the script `template/search.js` (served as `/asset/search.js`). The index holds `{id,title,url,kind,body}` for non-hidden, non-unlisted pages: `kind` is the namespace (`Topic`, `Commentary`, …, with ` notes` for a notes page) and `body` the page's whole tag-stripped text, with the entities markdown-it escapes (`&amp;`) decoded. The browser builds a MiniSearch index from it on each visit. The options are MiniSearch's own: `processTerm` lowercases, strips accents and transliteration's modifier letters (so `olam` finds `ʿôlām`) and drops stop words (a short English list, without "will" and "no") and lone letters (the "s" of "God's"), at indexing and in queries; `prefix` applies only to the last word typed; `fuzzy` (0.2) only to words of six letters or more; a title match counts double; a notes page's score is halved. Words are OR'd, so more matches rank higher. The search is live: each keystroke runs it, and `?q=` and `?page=` stay in the address. Each result is the page's title, its kind and an excerpt of about 180 characters from just before the first matched word (nothing is highlighted). MiniSearch reports the terms it matched, including the whole words a prefix or fuzzy query reached, but no positions, so `search.js` finds the first one in the page text it holds, with the same `processTerm`. The excerpt is cut between words, with `…` where it is cut, and a hit on the title alone starts at the top of the page. Twenty results make a page, with a count ("122 results") and, under them, links to the pages like the Scripture index's book-to-book links: `« Previous · 1 · … · 4 · 5 · 6 · … · 20 · Next »`, the current page bold and unlinked, the first and last page and two either side of the current one shown, a gap as `…`. Each is a real link (`?q=…&page=n`) that the script takes the click of. The field is focused on load and styled like the sidebar's.
- **Random**: `/random` redirects on the client to a random page from the alphabetical-index pool, minus the `category`, `meta` and `reference` namespaces. Its body (a Proverbs 16:33 quotation) is hardcoded.
- **Scripture index**: `/index/scripture` lists the referenced books. `/index/scripture/{book-slug}` is a `<dl>` with one `<dt>` per unique reference, which links to each page or section where that reference appears. Entries run by chapter, then verse; from the same start the longer range comes first (`John 3:16–4:2`, `3:16–20`, then `3:16`). References come from content pages, in any namespace except `reference` (whose pages are long citation tables); unlisted pages and notes pages are left out. Meta (root) pages and category pages are included. Each book's page has back and forward links to its neighbours (`« Malachi · Mark »`: the books that have a page), at the top and bottom, and a "Jump to chapter:" menu box (the chapters that have an entry, linking to their `#ch-N` anchors; the top box leaves out the first chapter and the bottom one the last; a book with one cited chapter has none). Commentary pages are in the index, labelled with the h2 or h3 they fall under. Each `<dt>` has an id, the short form of the reference with URL-friendly punctuation (`#3.16`, `#3.9-17`), and the first entry starting in a chapter holds an empty `<span id="ch-3">`; `lib/bible/collect.js` (`entryId`, `chapterId`) is the one place that defines both, and `/statistics` links to them.
- **Scripture index entries on a commentary page**: a commentary page named for a Bible book (its title is the book's full name, `Titus`; any other listed commentary page fails the build) carries that book's Scripture index entries between its paragraphs, in canonical order, behind an "Interleave Scripture index entries" switch, styled like an iOS toggle, centered at the foot of the page under the categories (a page with no entries has no switch). The entries start hidden and are left out of print, with the switch. The switch works without script. Two small inline scripts remember the choice for the whole site in `localStorage` (`scripture-entries`): one at the top of the page puts a class on `<html>` so the entries show from the first paint, and one after the switch keeps the checkbox and that class in step. The commentary is cut into slices: one starts at each `h2` (its position is the first reference in its parentheses, `Greeting (Tit 1:1–4)`) and at each term of a description list that opens with a reference to the book (`Tit 1:2 *God, who never lies*`); the terms and paragraphs after it belong to it, and a heading without a reference keeps the position before it. A description list is cut at those terms, and where no entries fall between two pieces they are one list again. An entry comes after the slice for its verse and before the first slice for a later one (an entry for a whole chapter comes before the chapter's first verse). The entries are marked up and styled as on the Scripture index page (`dl.scripture-entries`, with a `ch-N` anchor on the first entry in each chapter). The commentary page's own references are left out of the entries (they are in the text), and so is an entry no other page references. The entries need every page's references, so such a page is first processed with its text alone, which collects its references and writes nothing, and is written again, last, with the entries; they are not collected. Search, word counts and the description come from the commentary alone. The Scripture index always has a page for a book with a commentary page; if nothing references the book, not even its own commentary, the build fails.
- **Settings**: `/settings`, linked from the footer, after Colophon (it is not in any index, search or the sidebar). A static page; its choices live in the reader's browser (`localStorage`) and it needs script (a `<noscript>` note says so; the form is `hidden` until the script runs). *Theme*: System (the default), Light or Dark, as three tiles (`THEMES` in `lib/pages/settings.js`; the sun and the moon with stars, and for System a laptop at the sidebar's width, 800px, and a phone below it). The choice is saved as `theme` = `{mode, until}`; `until` is 12 hours out unless the reader turns on "Make my theme choice permanent" (then there is none), and a notice says which applies whenever the choice isn't System. For a temporary choice it counts down in whole hours ("in 12 hours", then 11, and so on, "within the hour" at the end; rounded up, never finer), refreshed every 30 seconds while the page is open, and the page goes back to System by itself when the time is up. Opening the page doesn't restart the 12 hours; making a choice there does. A script in every page's head (`layout.ejs`) reads it before first paint: it puts `data-theme="light"` or `"dark"` on `<html>` (and defines `window.applyTheme`, which the settings page uses and which also sets the `theme-color` metas to match), and removes a choice past its `until`. In `style.css` the dark variables are declared twice, with the same values: under `prefers-color-scheme: dark` for `:root:not([data-theme="light"])`, and for `:root[data-theme="dark"]`; print stays light. *Accessibility*: two switches, "Underline links" and "Underline abbreviations", both off by default (`UNDERLINE_DEFAULTS` in `lib/layout.js` is the one place that picks the defaults). The layout writes each default on `<html>` as `data-underline-links` and `data-underline-abbr` (`"on"` or `"off"`), and the head script replaces them with the reader's saved choices (`underline-links` and `underline-abbr` in `localStorage`, each kept only while it differs from its default, so changing a default reaches everyone who never went against it). `style.css` has a rule for `on` only. *Links*: every link is underlined except the logo, the social icons and the page tabs, which have a cue of their own, at low specificity so the links styled plain (footnote references and back-links) stay plain; the sidebar and footer links are underlined too, since they are the same color as the text around them. Every link also underlines on hover and keyboard focus, setting or not. *Abbreviations*: every `<abbr title>` gets the browser's usual dotted underline (`underline dotted`), which the plain `abbr { text-decoration: none }` otherwise removes. *Commentary pages*: the same "Interleave Scripture index entries" switch as at the foot of a commentary page, sharing its `scripture-entries` setting. *Stylesheet*: a switch, "View the site without any CSS", for the mode in `css-naked.js`. That is a blocking classic script in the head, ahead of the stylesheets, so a naked page never paints styled. Naked mode switches styles off instead of deleting them, so it works live, without a reload: stylesheets get `media="not all"`, inline `style` attributes are set aside (and the Font Awesome kit's SVGs hidden), and a `MutationObserver` does the same to what arrives later; turning it off puts everything back. The script publishes `window.cssNaked` (`get()`, `set(naked)`) and fires `cssnakedchange` on `window`. A banner offers the way back (or, on CSS Naked Day, the way in). The choice is `css-naked` in `localStorage`, or `css-naked-<year>` on the Day (April 9 anywhere; the first visit turns it on). `?css-naked` turns it on and is dropped from the address. Styles are in `settings.css` (linked on this page only) and the switch in `style.css`.
- **Statistics**: `/statistics`, the first generated page in the `meta` namespace (it opens with the Trees-and-buildings hero image at 300×137, like a content page) (it is in `/index/alphabetical/meta` and linked from the sidebar, with the lone `Meta page` tab). Everything on it is counted from structures the build already holds, with no extra pass over the files: counts by namespace, drafts, featured; words (totals, longest and shortest pages, the most used words, the divine names, Greek and Hebrew words); links (most linked to, pages nothing links to, a count of broken links, a cloud of the hidden pages they go to (most linked to first, with the number of pages linking), and a table of links out and in by namespace, each apart for content pages and notes pages; a broken link is one to a hidden page, which visitors reach as the "under construction" stub, counted once per pair of pages like the rest); categories; the headings, description terms (every `<dt>`, commentary pages' included), tables, footnotes and so on on the pages, and page weight; and Scripture: references, books, chapters and verses cited, the most cited books, chapters and verses, records, a heatmap of all 1,189 chapters, one dot each (a dot's shade is the share of the chapter's verses cited: none, up to 25%, up to 50%, up to 75%, over 75%, so short chapters can reach the top shade; a chapter cited only as a whole gets the first shade, and no number of such mentions raises it further), with each book's references beside its name and its chapters and verses cited (as percentages, with the fractions in a tooltip) under the name, on the left of its dots (each book takes the next theme color in hue order, pink last, looping after twelve books; the legend stays the primary green). A list of titles that is empty (pages nothing links to, broken links, uncategorized pages) is left out with its heading. The output is deterministic: no dates or timings, only the tsgen version and the content commit, which a footnote at the foot of the page links to their GitHub pages (a build with no commit prints its timestamp instead, as plain text with no link). The testaments get a block each: their books and references in words, then a pie each for the chapters and the verses cited (four pies in all, in the first four theme hues; the uncited rest of each is the pie's hue at the heatmap's 0–25% shade, in light and dark mode alike); the right-hand column is as wide as its widest figure, so a longer number moves the pie in rather than overflowing. A table whose last column is text (not figures) gets the `text-last` class, which makes the other columns shrink to fit. Hidden and unlisted pages are not counted anywhere, and there are no figures about them. The words, links, categories and page figures count the listed pages and their notes; the Scripture figures count the references on topic and commentary pages: notes pages and reference pages are not in the Scripture index, and Meta and category pages are in the index but are left out of these figures; there are two exceptions: the overview's total is every reference there is: the index's plus those on notes pages and reference pages (`output.otherRefs`, collected apart so the index never lists them), and a table at the top of the Scripture section breaks the references down by namespace, "On pages" and "In notes", reference pages and categories included. Verse coverage uses `lib/bible/versification.js`, the Protestant numbering (1,189 chapters, 31,102 verses). A chapter is *cited* when any citation touches it; a verse is *cited* only when a citation names it, on its own or in a range of fifteen verses or fewer (`MAX_CITED_RANGE` in `lib/stats.js`), so `Romans 5` cites the chapter but none of its verses, `Romans 12:1–15:13` cites its chapters but not its verses, and `Romans 5:1` cites both. Every ranked list numbers ties as shared places (1, 2, 2, 4: the `<li>` carries a `value` where its place differs from its position), and the most cited chapters and verses keep every entry tied with the tenth, so they can run past ten. Much of the page is links: the namespace names go to their alphabetical indexes; the word cloud goes to `/search?q=…`; the most cited chapters and verses, the longest passage and the widest chapter span go to their entries in the Scripture index (a chapter or verse with no entry of its own goes to the nearest earlier chapter's); and each cited heatmap dot goes to its chapter there, with `tabindex="-1"` so its roughly 900 links stay out of the tab order (the book's name leads to the same page). The uncited stretch is deliberately left unlinked (`!`). The big-number tiles run three across, each with its own hue (all twelve theme colors, in turn across the page) and, where one has been chosen, an icon as a big tilted watermark clipped by the rule on top (a tile can name its icon in `lib/pages/statistics.js`; without one it has none); the first tile of each group is its headline and spans two columns, and a short last row is stretched to fill it. On this page only (the `statistics` body class), the paragraph after an h3 is ordinary body text, neither muted nor indented; the h3 itself keeps the site's small caps. The computation is `lib/stats.js`, the page `lib/pages/statistics.js`; it adds about 26 ms to a build of about 500 ms.

## Post-processing (every `.html` under `dist/`, in order)

1. **Heading IDs**: every `<h2>`/`<h3>` without an `id` gets one (and, on every page but a commentary page, every `<dt>`: a topic page's terms are its section titles, so they are headings in everything that follows: the Scripture index's sections and the skip list below), using slugified text (HTML entities such as `&amp;` decoded first, so `Faith & Works` is `faith-and-works`). Existing IDs are kept and reserved first. A heading or term with the same name as the one just before it (an `h2` and the term under it that repeats its title) gets no id: a link, and a Scripture index entry, goes to the first. The same name anywhere else on a page **fails the build** (all of them are listed, with the page), since a link couldn't tell the two apart.
   A trailing block id (` ^5602cb`, as Obsidian writes it) is removed from the text on every page. On a definition of a topic page it is also the secret name of its term: `[[topic/Atonement#^5602cb]]` links to `/topic/atonement#<the term's id>`. `[[Page#Heading]]` links to an h2, h3 or topic-page term whose slug matches the text after `#`. A `#` link that matches nothing fails the build.
   - **Table of contents** (notes pages and commentary pages only, right after this pass): a `<nav class="toc">` listing the article's `h2` headings, each linked to its id, titled "Contents" ("Outline" on a commentary page). It goes in front of the first `h2`, after any introduction, and a page with fewer than three gets none. The `h3`s are left out. The title is a `<p>`, not a heading, so the Scripture collector doesn't take it for a section.
2. **Small asides** (every page with content, not a commentary page; generated pages are left alone): in a term (`<dt>`), an `<h3>` or a definition (`<dd>`), a parenthetical becomes `<small>` (in a term or heading its words are also wrapped in `<em>`, so the parentheses stay upright), and in a definition an em dash starts italic, small text, so the tildes and asterisks aren't needed: `~(like this)~` and `*~— like this~*`. The outermost pair of parentheses is wrapped (both must sit in the same element, so across a link or italics is fine), unless it is part of a word: `Son(s)` stays as written, because the `(` follows a letter or digit, or the `)` is followed by one. An em dash starts an `<em>` and a `<small>` that run to the end of the element holding it, the `<dd>` or its paragraph, dash included. Only the first dash in an element does; later ones are inside it. Nothing is wrapped twice with the same extent: parentheses with exactly the extent of an existing `<small>` are skipped, and a dash already inside an `<em>` or a `<small>` gets no second one. A smaller `<small>` inside a bigger one nests: parentheses inside an authored `~…~` or after a dash get their own. Left alone: a term or definition that is one pair of parentheses from start to end (it stays full size), a dash in a term, a dash inside parentheses, a dash with nothing after it (an empty definition's `—` placeholder), web addresses and code. Nested tildes don't nest (`~a ~(b)~ c~` is two pairs), so an authored `~…~` around an aside with its own `~(…)~` inside is a mistake in the content.
3. **Scripture collection and index generation**: see above. The index pages then get heading IDs and go through the remaining passes. Collection and step 3 are one pass (`lib/bible/process.js`): each text run is scanned for references once (`scan.js`), then linked, and on content pages collected.
4. **Bible reference linker**: turns references into `<a class="external bible-ref" href="https://ref.ly/{Abbr}{ch}[.{v}[-{v2}|-{ch2}.{v2}]|-{ch2}];{TRANS}">`.
   - Books are matched by full name or abbreviation, **case-sensitively** (`Ro 3:23`, not `ro 3:23`). A numbered book's abbreviation has **no space** after the number (`1Jn 2:2`, `2Ki 5`); `1 Jn 2:2` and `2 Ki 5` aren't references and don't link (`Jn` after a lone `1`, `2` or `3` and a space isn't read as John either). The full names (`1 John`, `2 Kings`) take the space. The abbreviations come from the last entry of each book's `names` list in `BIBLE_BOOKS`.
   - Formats: `Book ch`, `Book ch–ch`, `Book ch:v`, `Book ch:v–v`, `Book ch:v–ch:v`. A hyphen, a spaced hyphen or an em dash in a range is shown as an en dash in the link text (`Jn 3:16-18` reads `Jn 3:16–18`); an opted-out reference (`!Jn 3:16-18`) is left exactly as written.
   - Books of one chapter (Obadiah, Philemon, 2 John, 3 John, Jude) are written in full: `Phm 1:3` is verse 3 and `Phm 1:3–5` verses 3–5, and `Phm 1` is the whole letter. A lone number is a chapter, so `Phm 3` is chapter 3, which doesn't exist and fails the build (see below). They are shown without the chapter: `Phm 1:3` reads `Phm 3`, `Phm 1:3–5` reads `Phm 3–5`, and `Phm 1` or `Philemon 1` reads just `Phm` or `Philemon`, still linked to the whole chapter. A bare number after such a reference is a verse (`Jude 1:3, 5`). The links are always explicit (`Phm1.3`, `Phm1`), and the Scripture index lists the same entries.
   - **A reference that can't exist fails the build**, like a broken wikilink: a chapter or verse its book doesn't have (`Romans 17`, `Isaiah 16:40`, `Phm 3`), a range that runs backwards (`Jn 3:18–16`), or a number that is really something else read as a continuation (`Romans 12:1–15:13, 71 verses` reads the 71 as Romans 12:71). Every one is listed with its page and the reason, and a one-chapter book gets a hint on how to write the verse. It is checked against `lib/bible/versification.js` (the verse count of every chapter). Only published pages count: a hidden page is never rendered, and a page shown by `serve --show-hidden` only warns. A `!` before a reference opts it out (`!Romans 17` is plain text); a continuation can't be opted out, so reword it.
   - Continuations: after `;` or `,` with only whitespace in between, `ch:v` or a bare number carries the current book forward. What a bare number means depends on the reference before it:
     - after a chapter-level reference (`Romans 3`, `Romans 3–5`), it is a chapter, or a range of chapters: `Romans 3, 5` is chapters 3 and 5 (two links), `Romans 3, 5–7` is chapter 3 and chapters 5–7. A further bare number stays at chapter level (`Romans 3, 5, 7`), until a `ch:v` returns to verses.
     - after a reference with a verse (`Romans 3:16, 18`, and `Romans 3:16; 5` too), it is a verse in the last chapter, and after a run across chapters (`Romans 12:1–15:13, 20`) in the chapter the run ends in.
     - a `1`, `2` or `3` followed by a capitalized word is the start of a numbered book (`; 1 Tim 3:3`), not a continuation.
   - Translation: an `ESV|KJV|NASB|NIV|NKJV|NLT|NRSV` that directly follows a named reference and its continuations (only whitespace in between, as in `Jn 3:16; 5:24 KJV`) applies to all of them. Any word or punctuation in between, such as `Jn 3:16 (KJV)`, means it isn't about that reference. ESV is the default. The translation is moved inside the last link.
   - A reference prefixed with `!` is not linked.
   - Skipped inside `a`, `code`, `pre`, `script`, `style` and `h1`–`h6`, and, on every page but a commentary page, `dt`. (On a commentary page the terms are bold text: their references are linked and collected, and the section they fall under is the `h2`'s.) Context resets at block tags.
   - In the link text, spaces become non-breaking spaces and range dashes become en-dashes.
5. **Abbreviations**: before the wrapping passes, every all-caps word in the page's text (two or more capitals, then capitals or digits: `NASA`, `UBS5`; dotted forms such as `A.5` aren't looked for) must be a key of `abbreviations.json`, a Roman numeral or a divine name, or the build fails and lists the word with its page. This applies to generated pages too. Then each `abbreviations.json` key becomes `<abbr title="…">`. Matching is case-sensitive and longest-first. There is always a leading `\b`, and a trailing `\b` only when the key ends in a word character. Skipped inside `abbr`, `code`, `pre`, `script`, `style`, and in any web address (text from `http://`, `https://` or `www.` to the next whitespace, so a bare link's display text is left alone; this holds for the initials, Roman numeral and divine name passes too). Other anchors are *not* skipped. On a device without hover, a tap on an `abbr[title]` shows its title in a popover (`template/abbr-popover.js`, loaded as a module at the end of every page): one shared element, created on the first tap, in the top layer (the Popover API), so a tap elsewhere or Escape closes it, as does a second tap on the same abbreviation, a scroll or a resize. It sits just below the abbreviation (above it if there is no room), centered and kept on screen; the script positions it with inline styles, and `style.css` (`#abbr-popover`) gives it the look. It works whether or not the "Underline abbreviations" setting is on, and whether or not the abbreviation is underlined. An abbreviation has no tab stop, and one inside a link leaves the tap to the link. `title` stays for hover and screen readers. A `(hover: none)` rule gives the abbreviation `cursor: pointer`, because iOS Safari only delivers a tap to a script when the target looks clickable.
6. **Initials**: two or more consecutive `X.` (for example `C.S.`) become `<abbr title="…">`, the title coming from `initials.json`. The key is the initials and the surname beside them, `R.C. Sproul`, found whether the page reads `R.C. Sproul` or `Sproul, R.C.` (a surname before the initials wins, so `Carson, D.A. The…` isn't read as `D.A. The`). Initials with no entry, or with no surname beside them, **fail the build**, as on generated pages. Spaced initials (`D. A.`) aren't initials as far as the pass is concerned. Same skip list as abbreviations.
7. **Roman numerals**: valid uppercase numerals of two or more letters, and dotted pairs like `X.III`, become `<span class="roman-num">`. Same skip list.
8. **Divine names**: `LORD`, `GOD`, `YHWH`, `I AM` (+ ` THAT/WHAT/WHO I AM`) and `I WILL BE` (+ the same suffixes) become `<span class="divine-name">`. In each, the letters `G`, `L` and a standalone `I` are wrapped in `<span class="divine-name-initial">`, so `YHWH` gets no initial span. Same skip list.
9. **Spaced ellipses**: `. . .` becomes `.&nbsp;.&nbsp;.` (with a leading `&nbsp;` when preceded by whitespace). This applies everywhere in the file, with no skip list.
10. **Alt text**: an `<img>` whose `src` basename is a key in `alt-text.json` gets its `alt` set or replaced. Matching is case-sensitive. An `<img>` with no entry (or no `src`) **fails the build**, generated pages included.

These passes run over the **entire** HTML file, including `<head>`, except the `<title>` element, which is set aside first and put back untouched (it is plain text, so no pass may put markup in it).
